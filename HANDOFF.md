# HANDOFF.md — как продолжить работу над Ritmo

Читать по порядку: `AGENTS.md` → `PRODUCT.md` → `PROJECT_STATE.md` → `README.md`.

## Обстановка

- Проект `D:\Pr\ritmo`, ветка `main`, коммит и push без Pull Request и force-push.
- Сборка из Git Bash: `export JAVA_HOME=/d/Pr/tools/jdk;`
  `export GRADLE_USER_HOME=/d/Pr/tools/gradle-home; ./gradlew assembleDebug assembleRelease`.
- Версия: `./gradlew newVersion` (`ггмм.дд.номер`, `versionCode = ггммдд * 100 + номер`).
- Релиз: `gh release create vX dist/ritmo-X.apk dist/ritmo-X-debug.apk`.
- Подпись: `D:\Pr\keys\ritmo-release.jks` + `keystore.properties` (в git не попадают); ключ не менять.
- Проверка логики без устройства: `./gradlew -p D:/Pr/schedule-check run` — временный JVM-проект
  с копиями `Reminder.kt` и `Schedules.kt`, в репозиторий не входит. Перед запуском скопировать
  актуальные исходники в `D:\Pr\schedule-check\src\main\kotlin\com\tmksdm\ritmo\`.

## Точка продолжения

- Все три этапа реализованы. Этапы 1 и 2 утверждены, Этап 3 (`2610.18.9`) ожидает ревью
  и проверки на телефоне.
- Не делать: новые этапы и функции сверх `PRODUCT.md`, автоматические и облачные копии,
  синхронизацию, смену стека, публикацию ключа подписи.
- Следующий шаг: дождаться ревью и проверки; далее — только улучшения по итогам практики.

## Чек-лист ревьюера (ChatGPT)

1. Сверить коммит и релиз с отчётом: SHA, версия, `versionCode`, размер и подпись (`CN=Ritmo`).
2. `Backup.kt` и `Reminder.listFromBackup`: проверка файла до изменений, починка значений,
   отмена старых будильников, планирование только будущих срабатываний.
3. `Schedules.kt`: месячный перенос, окно интервалов, «каждые N дней», отсутствие дублей и пропусков.
4. Ошибка записи не должна выглядеть как успешное сохранение (`ReminderStore.save` → `Boolean`).
5. Дефекты UX указывать точечно, без переделки дизайна и расширения объёма работ.
6. Документация отражает факты; этапы не объявлять завершёнными до утверждения пользователем.

## Проверка на телефоне

Создать копию и восстановить её, попробовать повреждённый файл (данные должны остаться),
проверить срабатывания после восстановления, установить новую версию поверх предыдущей.
