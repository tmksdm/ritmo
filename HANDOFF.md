## Текущая работа: теги вместо групп

- Модель: `Reminder.group` заменён на `Reminder.tags: MutableList<String>`; пустой список —
  без тегов. JSON пишет `tags`, старое поле `group` читается как первый тег и больше не пишется.
  `Reminder.sanitized` нормализует теги.
- Правила названий: `TagNames.kt` — trim, пустые отбрасываются, длина до 60, уникальность
  без учёта регистра, переименование с изменением регистра разрешено.
- Хранилище: `Tags.kt` — `tags.json` через `AtomicFile`; чтение идёт через `openRead`,
  который восстанавливает основной файл из `.bak`. При первой загрузке `Tags.migrateLegacyGroups`
  читает старый `groups.json` и переносит принадлежность из `group`; пустые группы становятся
  пустыми тегами. Напоминания без группы тег не получают, техническая секция «Без группы»
  не переносится. Завершение миграции (`ritmo_tags/groups_migrated_v1`) фиксируется только
  после успешного сохранения `reminders.json` (если были старые поля) и `tags.json`.
  Отдельный `groups_imported_v1` не даёт повторно читать `groups.json` после частичного сбоя,
  поэтому удалённые теги не возвращаются. `groups.json` остаётся только для чтения.
- Список: `ReminderOrdering.kt` — единый список, прежняя хронология (активные по ближайшему,
  выключенные, завершённые; tie-breakers — название и id) и фильтр по тегу без учёта регистра.
  Секций, свёрнутости и alias «Без группы» больше нет; `Groups.kt`, `ReminderGroups.kt`
  и `item_group_header.xml` удалены.
- Главный экран: в шапке кнопка «Теги» открывает менеджер (создание, переименование, удаление).
  Теги строки — чипы рядом с переключателем; нажатие включает фильтр, полоса «Фильтр: …»
  имеет кнопку «Сбросить», повторное нажатие тега тоже сбрасывает. Пустой результат объяснён.
  Меню напоминания: «Изменить», «Удалить». Переименование и удаление тега сначала сохраняют
  определения в `tags.json`, затем назначения; при ошибке определения откатываются,
  а изменения не выдаются за успех.
- Экран создания/редактирования: чипы существующих тегов, множественный выбор, автосохранение.
  Если тегов нет, показывается подсказка создать их кнопкой «Теги» на главном экране.
- Резервные копии: `Backup.restore` сохраняет напоминания и добавляет недостающие определения
  тегов, не удаляя существующие; старые копии с `group` поддерживаются. Пустые определения
  тегов в копию не входят.
- Расписания, `AlarmManager`, уведомления, настройки, обновления и `version.properties`
  не менялись. Новых зависимостей нет.

## Оставшиеся ограничения по ревью

- При редком сбое миграции могут не перенестись пустые определения групп; назначенные теги
  при этом сохраняются.
- Резервная копия сохраняет только назначенные теги; определения пустых тегов в неё не входят.
- Если `reminders.json` доступен только как `.bak`, первая загрузка может быть пустой;
  сам файл не теряется.

## Порядок работы и следующий шаг

1. Проверка пользователем на телефоне: теги у переключателя, фильтр/сброс/пустой результат,
   создание/переименование/удаление, несколько тегов, сохранение расписаний, миграция
   установленной версии с группами.
2. B1 закрыт, секреты и alias загружены. Этот коммит публикует workflow; следующий
   шаг — первый server run `publish_release=false` и проверка artifact. Release создаётся
   только отдельным запуском из `main` с `publish_release=true` и тегом `v<versionName>`,
   когда версия согласована. Новые этапы самостоятельно не начинать.

## Чек-лист ревьюера

1. Модель: `Reminder.tags`, `tags.json`, `TagNames`; старый `group` читается, новый JSON
   не пишет `group`; несколько тегов и пустой список допустимы.
2. Миграция: `tags.json` + `group` из старого `reminders.json`; пустые группы; отсутствие
   обязательного тега «Без группы»; повторный запуск не возвращает удалённый тег;
   ошибка записи не выдаётся за успех.
3. Список и фильтр: прежняя хронология, отсутствие секций, чипы у переключателя,
   активный фильтр назван, сброс кнопкой и повторным нажатием, пустой результат.
4. CRUD тегов: уникальность без учёта регистра, переименование обновляет назначения,
   удаление снимает тег без удаления напоминаний, пустые теги сохраняются.
5. Совместимость: старая и новая копия, импорт не теряет напоминания и теги, расписания
   и будильники не меняются; `version.properties` не изменён.
6. Сборка и `lintVital`/`lintDebug`; на устройстве проверить темы, отступы и читаемость
   длинных тегов. Дефекты указывать точечно, объём не расширять.
7. CI: workflow только `workflow_dispatch`; fail-fast без секретов; подпись обязательна
   (`RITMO_REQUIRE_RELEASE_SIGNING`); проверяются ровно одна подпись и SHA-256 сертификата,
   `package`, `versionName`/`versionCode`, `minSdk`/`targetSdk`, размер ≤ 5 МиБ; debug APK
   отсекается; artifact содержит подписанный APK и SHA-256.
8. Публикация: только из `main`, только при `publish_release=true` и точном теге
   `v<versionName>`; существующие тег/релиз не перезаписываются. Новый Release и версия
   в этом этапе не создавались.
9. Секреты: в Git и документации нет значений ключа/паролей; bootstrap-скрипт не печатает
   их и загружает через `gh` из файлов вне репозитория.
