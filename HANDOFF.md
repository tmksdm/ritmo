## Текущая работа: годовые повторы, группы и UI-правки

- Годовой повтор: `RepeatType.YEARLY`, поля `monthOfYear`, `dayOfMonth`, расчёт в
  `Schedules.nextYearly`. 29 февраля: 28 февраля в невисокосный год, снова 29 февраля
  в високосный; отсутствующее в месяце число заменяется последним днём месяца.
  В `EditActivity` — месяц и день, время; вид в списке — `Formats.scheduleDescription`.
- Группы: принадлежность хранится в напоминании (`Reminder.group`), названия групп —
  в `groups.json` (`Groups.kt`), свёрнутость — в `SharedPreferences`.
  Сортировка и секции — `ReminderGroups.kt` (без Android-зависимостей, проверяется на JVM).
- Порядок: внутри групп прежний; группы — по ближайшему активному срабатыванию,
  без предстоящих вниз; tie-breakers — название и исходный порядок. Свёрнутая группа
  участвует в сортировке. «Без группы» появляется только при наличии групп; без групп
  список плоский. Удаление группы снимает назначение, но не удаляет напоминания.
- Совместимость: старый JSON без `group`/`monthOfYear` читается без миграции; отсутствие
  `groups.json` — это отсутствие групп. Названия групп входят в резервную копию в составе
  напоминаний; пустые группы в копию не попадают.
- Alias секции без группы: `Groups.ungroupedName`/`setUngroupedName` в `SharedPreferences`.
  Внутреннее назначение остаётся `null`; alias показывается в заголовке и диалоге перемещения.
  Проверка занятости названий — `ReminderGroups.nameIsTaken`; удаление специальной секции
  не предлагается.
- Конфликт из старых данных/импорта: `Groups.resolveUngroupedName` вызывает
  `ReminderGroups.freeUngroupedName`, подбирает свободный суффикс « (2)», « (3)» и сохраняет
  его; вызывается при каждой загрузке списка и после импорта. Реальные группы и назначения
  напоминаний не меняются, повторная загрузка не создаёт новые имена.
- Диалоги группы используют `dialog_group_name.xml`: контейнер с `dialogPreferredPadding`,
  поле без горизонтального padding, `selectAllOnFocus`. Все `EditText` на экране
  редактирования также получили `selectAllOnFocus`; повторное касание внутри поля
  не перехватывается.
- Заголовок группы: меню видно и у секции без группы (только «Переименовать»),
  content description включает название; счётчики выровнены.

## Обстановка

- Проект `D:\Pr\ritmo`, ветка `main`, работа без Pull Request и force-push.
- Сборка: `export JAVA_HOME=/d/Pr/tools/jdk; export GRADLE_USER_HOME=/d/Pr/tools/gradle-home;`
  `./gradlew assembleDebug assembleRelease`.
- Версия: `./gradlew newVersion` (`ггмм.дд.номер`, `versionCode = ггммдд * 100 + номер`).
- Релиз (по отдельному указанию пользователя): `gh release create vX dist/ritmo-X.apk`.
  В релиз кладётся только подписанный release APK без «debug» в имени — именно его
  выбирает встроенный updater. Подпись — `D:\Pr\keys\ritmo-release.jks` с `keystore.properties`
  (в git не попадают), ключ не менять.
- Проверка логики без устройства: `./gradlew -p D:/Pr/schedule-check run` — временный JVM-проект
  с копиями `Reminder.kt`, `Schedules.kt`, `ReminderGroups.kt`; перед запуском скопировать
  туда исходники. Сейчас 88 сценариев, все проходят (включая занятость названий
  и разрешение конфликтов alias с реальными группами).

## Оформление

- Единственный источник правды по стилю — `DESIGN.md`; эталонная проработка — `index.html`
  пользователя (вне репозитория), направление 1.
- Цвета, радиусы и состояния заданы токенами-атрибутами (`ritmo*` в `values/attrs.xml`).
  Разметка и drawable ссылаются на атрибуты, поэтому правка цвета делается один раз
  в `values/colors.xml` и `values/themes.xml` (+ `values-v27/themes.xml`).
- Тема задаётся целиком в каждом файле тем: `values/themes.xml` — для API 26,
  `values-v27/themes.xml` — для API 27+. При правке менять оба согласованно.
- Заголовок группы использует существующие токены и `ic_chevron_right` с поворотом;
  новых цветов и зависимостей нет.

## Порядок работы над заданием

1. Сверить объём с `PRODUCT.md`; сверх задания ничего не добавлять.
2. Внести изменения, собрать debug и release, проверить версию и подпись.
3. Обновить документацию: устаревшее заменять, историю не накапливать.
4. Коммит в `main`, push, GitHub Release — только по указанию пользователя.
5. Остановиться до проверки пользователем.

## Чек-лист ревьюера (ChatGPT)

1. Сверить SHA коммита и релиз `v2610.25.2`: версия `2610.25.2` (`26102502`), подпись
   `CN=Ritmo`, APK-ассет без «debug» в имени, tag указывает на опубликованный коммит.
2. Проверить UI-правки: меню и выравнивание счётчика у секции без группы, alias после
   перезапуска и в диалоге перемещения, запрет совпадения с реальной группой, отступы
   полей диалогов, `selectAllOnFocus` без помех частичной правке и preview.
   Отдельно проверить конфликт из старых данных/импорта: секция получает суффикс,
   реальная группа не переименовывается, повторная загрузка не меняет имя снова.
3. Проверить годовую логику: 29 февраля в високосный и невисокосный год, смена года,
   отсутствующее число месяца, неизменность остальных видов повторов.
4. Проверить группы: создание/перемещение/снятие, переименование и удаление без потери
   напоминаний, сохранение свёрнутости, сортировку групп и «Без группы», плоский вид
   при отсутствии групп.
5. Проверить совместимость: старый `reminders.json` без новых полей, отсутствие `groups.json`,
   импорт старой и новой копии, отказ импорта не меняет данные.
6. Проверить, что ошибка записи не выглядит как успешное сохранение; оформление — на токенах,
   без изменения структуры экранов сверх необходимого.
7. Дефекты указывать точечно, без переделки дизайна и расширения объёма работ; ничего
   не объявлять завершённым до проверки пользователем.
