## Обстановка

- Проект `D:\Pr\ritmo`, ветка `main`, коммит и push без Pull Request и force-push.
- Сборка: `export JAVA_HOME=/d/Pr/tools/jdk; export GRADLE_USER_HOME=/d/Pr/tools/gradle-home;`
  `./gradlew assembleDebug assembleRelease`.
- Версия: `./gradlew newVersion` (`ггмм.дд.номер`, `versionCode = ггммдд * 100 + номер`).
- Релиз: `gh release create vX dist/ritmo-X.apk dist/ritmo-X-debug.apk`. Подпись —
  `D:\Pr\keys\ritmo-release.jks` с `keystore.properties` (в git не попадают), ключ не менять.
- Проверка логики без устройства: `./gradlew -p D:/Pr/schedule-check run` — временный JVM-проект
  с копиями `Reminder.kt` и `Schedules.kt`; перед запуском скопировать туда исходники.

## Оформление

- Единственный источник правды по стилю — `DESIGN.md`; эталонная проработка — `index.html`
  пользователя (вне репозитория), направление 1.
- Цвета, радиусы и состояния заданы токенами-атрибутами (`ritmo*` в `values/attrs.xml`).
  Разметка и drawable ссылаются на атрибуты, поэтому правка цвета делается один раз
  в `values/colors.xml` и `values/themes.xml` (+ `values-v27/themes.xml`).
- Тема задаётся целиком в каждом файле тем: `values/themes.xml` — для API 26,
  `values-v27/themes.xml` — для API 27+. При правке менять оба согласованно.
- Switch настраивается прямо в разметке (`android:track` / `android:thumb`): стиль
  с родителем `Widget.DeviceDefault.CompoundButton.Switch` не собирается — он приватный.
- Выбранный пресет времени выделяется через `android:state_selected`, чипы дней недели
  и единиц интервала — через `state_checked`; текст чипов берётся из `res/color/`.

## Порядок работы над заданием

1. Сверить объём с `PRODUCT.md`; сверх задания ничего не добавлять.
2. Внести изменения, собрать debug и release, проверить версию и подпись.
3. Обновить документацию: устаревшее заменять, историю не накапливать.
4. Коммит в `main`, push, GitHub Release, отчёт с SHA, ссылкой и размером APK.
5. Остановиться до проверки пользователем.

## Чек-лист ревьюера (ChatGPT)

1. Сверить коммит и релиз с отчётом: SHA, версия, `versionCode`, размер и подпись (`CN=Ritmo`).
2. Проверить изменённую логику по существу (`Schedules.kt`, `Backup.kt`, `ReminderStore.save`).
3. Оформление: обе темы собраны из одного набора токенов, акцент только на действиях,
   логика и структура экранов не изменились; при замечаниях к стилю править токены,
   а не подставлять цвета в разметку.
4. Отказ импорта не меняет данные; ошибка записи не выглядит как успешное сохранение.
5. Дефекты указывать точечно, без переделки дизайна и расширения объёма работ; ничего
   не объявлять завершённым до проверки пользователем.
