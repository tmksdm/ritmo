# HANDOFF.md — как продолжить работу над Ritmo

Порядок чтения: `AGENTS.md` (правила) → `PRODUCT.md` (требования) →
`PROJECT_STATE.md` (состояние) → `README.md` (сборка и установка).

## Рабочая обстановка

- Проект `D:\Pr\ritmo`, ветка `main`, коммит и push без Pull Request и force-push.
- Сборка из Git Bash: `export JAVA_HOME=/d/Pr/tools/jdk;`
  `export GRADLE_USER_HOME=/d/Pr/tools/gradle-home; ./gradlew assembleDebug assembleRelease`.
  SDK подключается через `local.properties`.
- Версия: `./gradlew newVersion` — `ггмм.дд.номер`, `versionCode = ггммдд * 100 + номер`.
- Релиз: `gh release create vX dist/ritmo-X.apk dist/ritmo-X-debug.apk`.
- Проверка логики расписаний без устройства: временный JVM-проект `D:\Pr\schedule-check`
  (копирует `Reminder.kt` и `Schedules.kt`, гоняет сценарии) —
  `./gradlew -p D:/Pr/schedule-check run`. В репозиторий не входит.
- Подпись: `D:\Pr\keys\ritmo-release.jks` + `keystore.properties` (в git не попадают).
  Ключ менять нельзя — иначе обновления перестанут устанавливаться.

## Текущая задача и границы

- В работе: Этап 2 — шесть видов расписания, окно интервалов, редактирование, восстановление
  расписания; плюс две UX-правки (пресеты выделяются фоном без галочки, кнопки плоские без теней).
- Не делать: Этап 3 (экспорт/импорт), смену стека, новые зависимости, переработку механизма
  уведомлений без причины, публикацию ключа подписи.
- Следующий шаг: дождаться ревью и проверки выпуска на телефоне, затем Этап 3.

## Чек-лист ревьюера (ChatGPT)

1. Сверить коммит и релиз с отчётом: SHA, версия, `versionCode`, размер и подпись (`CN=Ritmo`).
2. `Schedules.kt`: перенос месячного дня на последний день месяца, окно интервалов (отсчёт от начала,
   допустимость момента окончания), «каждые N дней» от даты начала.
3. `ReminderReceiver.kt`: отсутствие дублей и накопления пропущенных срабатываний.
4. Ошибка записи не должна выглядеть как успешное сохранение (`ReminderStore.save` → `Boolean`).
5. Реальные дефекты UX указывать без переделки дизайна и расширения объёма работ.
6. Документация должна отражать факты и не объявлять Этап 2 завершённым до утверждения.

## Что проверить пользователю на телефоне

Напоминания всех шести типов, окно интервалов, редактирование, включение/выключение,
срабатывание после перезагрузки, смена темы, обновление приложения из настроек.
