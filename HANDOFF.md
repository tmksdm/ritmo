# HANDOFF.md — как продолжить работу над Ritmo

Читать по порядку: `AGENTS.md` → `PRODUCT.md` → `PROJECT_STATE.md` → `README.md`.

## Обстановка

- Проект `D:\Pr\ritmo`, ветка `main`, коммит и push без Pull Request и force-push.
- Сборка из Git Bash: `export JAVA_HOME=/d/Pr/tools/jdk;`
  `export GRADLE_USER_HOME=/d/Pr/tools/gradle-home; ./gradlew assembleDebug assembleRelease`.
- Версия: `./gradlew newVersion` (`ггмм.дд.номер`, `versionCode = ггммдд * 100 + номер`).
- Релиз: `gh release create vX dist/ritmo-X.apk dist/ritmo-X-debug.apk`.
- Подпись: `D:\Pr\keys\ritmo-release.jks` + `keystore.properties` (в git не попадают); ключ не менять.
- Логика расписаний без устройства: `./gradlew -p D:/Pr/schedule-check run` (временный JVM-проект
  с копией `Reminder.kt` и `Schedules.kt`, в репозиторий не входит).

## Задача и границы

- Готово к ревью: Этап 2 — шесть видов расписания, окно интервалов, редактирование,
  восстановление расписания; плюс пресеты без галочки и плоские кнопки.
- Не делать: Этап 3 (экспорт/импорт), смену стека, новые зависимости, переработку
  механизма уведомлений без причины, публикацию ключа подписи.
- Следующий шаг: ревью и проверка выпуска на телефоне, затем Этап 3.

## Чек-лист ревьюера (ChatGPT)

1. Сверить коммит и релиз с отчётом: SHA, версия, `versionCode`, размер и подпись (`CN=Ritmo`).
2. `Schedules.kt`: перенос месячного дня на последний день, окно интервалов (отсчёт от начала,
   окончание окна при попадании на шаг), «каждые N дней» от даты начала.
3. `ReminderReceiver.kt`: нет дублей и накопления пропущенных срабатываний.
4. Ошибка записи не должна выглядеть как успешное сохранение (`ReminderStore.save` → `Boolean`).
5. Дефекты UX указывать точечно, без переделки дизайна и расширения объёма работ.
6. Документация отражает факты; Этап 2 не объявлять завершённым до утверждения.

## Проверка на телефоне

Напоминания всех шести типов, окно интервалов, редактирование, включение/выключение,
срабатывание после перезагрузки, смена темы, обновление приложения из настроек.
