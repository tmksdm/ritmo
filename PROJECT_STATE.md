## Что реализовано

Полные требования — в `PRODUCT.md`, оформление — в `DESIGN.md`, здесь только фактическое состояние.

- Семь видов расписания и необязательное окно времени суток для интервалов; расчёт по календарю
  (`Schedules.kt`). Повторы планируются заново, дубли отсекаются, пропущенные не накапливаются,
  расписание восстанавливается после перезагрузки, смены времени и обновления APK.
- Ежегодный повтор (`RepeatType.YEARLY`, `Schedules.nextYearly`): месяц и день, расчёт по
  календарю. 29 февраля срабатывает 28 февраля в невисокосный год и снова 29 февраля
  в високосный; отсутствующее в месяце число заменяется последним днём месяца.
- Теги (`Reminder.tags`, `Tags.kt`, `TagNames.kt`): несколько тегов у напоминания, названия
  в `tags.json`, чипы рядом с переключателем активности, единый список без секций.
  Нажатие на тег фильтрует список, полоса фильтра показывает название и кнопку «Сбросить»;
  повторное нажатие снимает фильтр. Кнопка «Теги» в шапке создаёт, переименовывает и удаляет
  теги. Удаление снимает тег с напоминаний, но не удаляет их. Переименование и удаление
  сохраняют сначала определения, затем назначения; при ошибке записи изменения откатываются
  и не показываются как успешные.
- Сортировка (`ReminderOrdering.kt`): прежняя хронология — активные по ближайшему срабатыванию,
  затем выключенные, затем завершённые; tie-breakers — название и id. Фильтр по тегу не меняет
  порядок и данные.
- Миграция: при первой загрузке названия старых групп из `groups.json` и принадлежность из
  поля `group` переносятся в теги. Пустые группы становятся пустыми тегами; напоминания без
  группы не получают обязательный тег; техническая секция «Без группы» не переносится.
  Чтение `tags.json` и проверка старого поля `group` в `reminders.json` используют
  `AtomicFile.openRead` с восстановлением из `.bak`. Завершение (`groups_migrated_v1`)
  фиксируется только после успешной записи напоминаний и `tags.json`; отдельный `groups_imported_v1` исключает повторное чтение
  `groups.json` после частичного сбоя, поэтому удалённые теги не возвращаются.
- Совместимость: старый `reminders.json` и старая резервная копия с полем `group` читаются
  без потери напоминаний; группа становится первым тегом. Новый JSON пишет `tags`.
  Названия тегов входят в резервную копию внутри напоминаний; определения пустых тегов
  в файл копии не попадают.
- Точные уведомления `AlarmManager` с разрешениями `SCHEDULE_EXACT_ALARM` и `POST_NOTIFICATIONS`;
  после выдачи доступа к точным будильникам активные напоминания перепланируются.
- Резервные копии (`Backup.kt`): экспорт и импорт JSON через системные диалоги, проверка файла
  до изменений, подтверждение замены, запись через `AtomicFile`, перепланирование после импорта;
  после импорта недостающие определения тегов добавляются, существующие не удаляются.
- Интерфейс: три режима темы, сортировка списка, меню действий, отступы от системных панелей.
  Обновление из приложения — по запросу, с проверкой `versionCode` и подписи перед установкой.
- Оформление: токены в атрибутах тем `Theme.Ritmo` / `Theme.RitmoDark`, поэтому светлая и тёмная
  темы собраны из одного набора правил. Акцент применяется только к действиям и выделению.
- Подписанный CI-релиз (`.github/workflows/release.yml`): только ручной `workflow_dispatch`;
  ключ передаётся через Actions Secrets, `keystore.properties` в CI не создаётся
  (ключ временно декодируется в `$RUNNER_TEMP`). До сборки workflow
  падает при отсутствии подписи, после сборки проверяет одну release-подпись и SHA-256
  сертификата, `package`, версию, `minSdk`/`targetSdk`, размер ≤ 5 МиБ. Artifact содержит
  `ritmo-<versionName>.apk` и SHA-256; Release создаётся отдельным запуском из `main`
  только при точном теге `v<versionName>`. Debug APK отсекается проверкой сертификата.
  Загрузка секретов — `scripts/set-github-signing-secrets.ps1`, значения не выводятся.

## Известные ограничения

- GitHub Actions workflow ещё не запускался: первый server run ожидается после push
  этого коммита. Release не публиковался; отладочная ветка подписи через env проверена
  только временным ключом, не постоянным.
- Интерфейс тегов, фильтр и миграция на реальном устройстве не проверены: в окружении
  разработки нет эмулятора и подключённого телефона.
- Редкий сбой миграции может не перенести пустые определения групп; назначенные теги
  при этом сохраняются.
- Резервная копия сохраняет только назначенные теги: определения пустых тегов в копию
  не попадают.
- Если `reminders.json` доступен только как `.bak`, первая загрузка может показать пустой
  список; сам файл не теряется.
- Старый `groups.json` остаётся на диске и больше не используется; миграция выполняется один раз.
- На Android 8 (API 26) нижняя системная панель остаётся тёмной: эта версия не умеет тёмные
  значки на ней, а светлая панель сделала бы значки невидимыми.
- В режиме Doze система может задержать срабатывание; ограничения не обходятся.
- Однократное напоминание, момент которого пришёлся на выключенное устройство, не восстанавливается.
- Окна интервалов через полночь не поддерживаются.
- Автоматического и облачного резервного копирования нет — копии создаются вручную.
