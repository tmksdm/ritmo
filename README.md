# Ritmo

Минималистичное Android-приложение напоминаний. Напоминания приходят как обычные
системные уведомления, созданные через точные будильники `AlarmManager`.

Документация проекта: `PRODUCT.md` (требования), `PROJECT_STATE.md` (текущее состояние),
`DESIGN.md` (оформление и токены), `AGENTS.md` (правила разработки),
`HANDOFF.md` (как продолжить работу).

## Возможности

- Семь видов расписания: однократно; через интервалы (минуты или часы); ежедневно;
  еженедельно по выбранным дням недели; ежемесячно (если числа в месяце нет — последний день);
  каждые N дней; ежегодно в выбранные месяц и день (29 февраля — 28 февраля в невисокосный
  год и снова 29 февраля в високосный).
- Временное окно для интервалов: по умолчанию выключено (круглосуточно), интервал отсчитывается
  от начала окна, ночью уведомлений нет. Окна в пределах одних суток.
- Расчёт срабатываний по календарю, а не от момента открытия приложения; пропущенные
  срабатывания не накапливаются.
- Быстрый выбор времени при создании: через 15 минут, через 1 час, завтра утром (09:00).
  Выбранный пресет выделяется фоном, время можно изменить вручную.
- Список напоминаний: описание расписания, ближайшее срабатывание, переключатель активности,
  меню действий (изменить, удалить). Сортировка: активные по ближайшему срабатыванию,
  затем выключенные, затем завершённые; список единый, без секций групп.
- Теги: несколько тегов у одного напоминания, чипы рядом с переключателем активности.
  Нажатие на тег фильтрует список, полоса фильтра показывает его название и кнопку
  «Сбросить». Кнопка «Теги» в шапке создаёт, переименовывает и удаляет теги;
  удаление снимает тег с напоминаний, но не удаляет их.
- Старые пользовательские группы и их принадлежность переносятся в теги с теми же
  названиями; пустые группы становятся пустыми тегами. Напоминания без группы не получают
  обязательный тег, техническая секция «Без группы» в тег не превращается.
- Текстовые и числовые поля при получении фокуса выделяют значение для быстрой замены;
  повторное нажатие внутри поля позволяет поставить курсор. Поля диалогов тегов выровнены
  по заголовку.
- Редактирование и удаление напоминаний, включение и отключение.
- Точные системные уведомления (`setExactAndAllowWhileIdle`), открытие приложения по нажатию,
  смахивание не отменяет будущие срабатывания.
- Восстановление расписания после перезагрузки, смены времени и часового пояса, обновления APK.
- Темы: системная, светлая, тёмная. Оформление «Тихий минимализм»: обе темы собраны из одного
  набора токенов (`DESIGN.md`), акцент применяется только к действиям и выделению, системные
  панели — цвета фона экрана, иконки Material Design, отступы от системных панелей.
- Локальное хранение в JSON во внутреннем каталоге приложения (запись через `AtomicFile`).
- Ручные резервные копии: экспорт всех напоминаний в JSON через системный диалог сохранения
  и восстановление из файла с проверкой данных и подтверждением замены.
- Обновление из приложения: «Настройки» → «Обновления». Проверка последнего релиза
  `tmksdm/ritmo` по запросу, сравнение по `versionCode`, загрузка APK по HTTPS,
  проверка подписи, установка системным установщиком. Фонового опроса нет.

## Сборка

Требования: JDK 17, Android SDK с `platforms;android-35` и `build-tools;35.0.0`.

```sh
# путь к Android SDK указывается в local.properties: sdk.dir=D:/path/to/android-sdk
export JAVA_HOME=/path/to/jdk17
./gradlew assembleRelease    # app/build/outputs/apk/release/app-release.apk
./gradlew assembleDebug      # app/build/outputs/apk/debug/app-debug.apk
```

Release-сборка включает R8 и удаление неиспользуемых ресурсов.

## Подпись и выпуск релизов

Все выпуски подписываются одним постоянным ключом — без него Android не позволит
обновить установленное приложение.

- Ключ: `D:\Pr\keys\ritmo-release.jks` (лежит вне репозитория и в Git не попадает).
- Параметры подключения: `keystore.properties` в корне проекта (в Git не попадает).
- Если файла `keystore.properties` нет, локальная release-сборка получает debug-подпись —
  это удобно для проверки, но такой APK нельзя публиковать. В GitHub Actions включён
  обязательный режим подписи, а проверка сертификата не пропускает debug APK.

Храните ключ и пароль к нему в надёжном месте: с их потерей обновления станут невозможны.

### Выпуск с любого компьютера (GitHub Actions)

Ключ не привязан к исходной машине: на новом компьютере достаточно ключа и
`keystore.properties`, а CI получает ключ из GitHub Actions Secrets. В репозитории
нет ни ключа, ни паролей.

Один раз на машине с ключом:

```powershell
pwsh -NoProfile -File scripts/set-github-signing-secrets.ps1
# ключ в другом месте:
pwsh -NoProfile -File scripts/set-github-signing-secrets.ps1 -Keystore D:\keys\ritmo-release.jks
```

Скрипт читает ключ и `keystore.properties`, передаёт значения в stdin процесса `gh`
без добавления перевода строки; `--body` и аргументы командной строки для секретов
не используются. Значения не выводятся. Имена:

- Secrets: `RITMO_KEYSTORE_BASE64` (ключ в base64), `RITMO_KEYSTORE_PASSWORD`,
  `RITMO_KEY_PASSWORD`.
- Variables: `RITMO_KEY_ALIAS`.

Ожидаемый SHA-256 сертификата постоянного ключа закреплён в workflow:
`913ccbab919ca5bb13a889f50b5d02567febb72806f237c40ce80cbec8bcfad9`
(`CN=Ritmo, O=tmksdm, C=RU`). Отдельная переменная для него не нужна.

Workflow `.github/workflows/release.yml` запускается только вручную и становится доступен
после публикации файла в `main`.

Собрать и получить artifact без публикации:

```sh
gh workflow run release.yml --repo tmksdm/ritmo -f publish_release=false
gh run list --repo tmksdm/ritmo --workflow release.yml
gh run download <run-id> --repo tmksdm/ritmo -n ritmo-<versionName>-signed
```

Создать GitHub Release можно только отдельным запуском из `main`, когда версия уже
согласована. Тег должен точно совпадать с `v<versionName>` из `version.properties`:

```sh
gh workflow run release.yml --repo tmksdm/ritmo \
  -f publish_release=true -f release_tag=v<versionName>
```

Workflow до сборки падает, если не заданы секреты, а после сборки проверяет: одну
release-подпись с ожидаемым SHA-256 сертификата, `package`, `versionName`/`versionCode`,
`minSdk`/`targetSdk` и размер APK не больше 5 МиБ. Debug-подпись не проходит проверку.
В artifact и Release попадает только `ritmo-<versionName>.apk` и его SHA-256.

CI использует предустановленный Android SDK из `ubuntu-latest`. Если его состав изменится
и проверка сообщит об отсутствии `platforms;android-35` или `build-tools;35.0.0`, добавьте
перед сборкой явную установку:

```sh
yes | sdkmanager --licenses
sdkmanager "platforms;android-35" "build-tools;35.0.0"
```

## Установка

```sh
adb install -r app/build/outputs/apk/release/app-release.apk
```

Или скачать APK из GitHub Releases на телефон и открыть (потребуется разрешить установку
из неизвестных источников).

## Версии

Схема версий: `ггмм.дд.номер`, где `гг` — год, `мм` — месяц, `дд` — день,
`номер` — порядковый номер сборки за этот день. Первая версия дня идёт без номера,
последующие — `2610.18.2`, `2610.18.3` и так далее.

Единственный источник версии — файл `version.properties`. Оттуда значение попадает
и в `versionName`, и в `versionCode` (`ггммдд * 100 + номер`). Установленную версию
видно в приложении: «Настройки».

```sh
./gradlew newVersion        # 2610.18 -> 2610.18.2 -> 2610.18.3, в новый день снова 2610.18
./gradlew assembleRelease
```

## Разрешения

- `POST_NOTIFICATIONS` — показ уведомлений (Android 13+), запрашивается при первом запуске.
- `SCHEDULE_EXACT_ALARM` — точные будильники (Android 12+). Если доступ не выдан,
  приложение предупреждает об этом, а расписание становится менее точным. После выдачи
  доступа активные напоминания перепланируются.
- `RECEIVE_BOOT_COMPLETED` — восстановление расписания после перезагрузки.
- `INTERNET` — только проверка и загрузка обновления из GitHub Releases по запросу.
- `REQUEST_INSTALL_PACKAGES` — запуск системного установщика при обновлении.

`USE_EXACT_ALARM` не используется: он ограничен политиками распространения приложений.

## Резервные копии

Раздел «Резервные копии» в настройках.

**Создать копию** — открывается системный диалог сохранения, предлагается имя вида
`ritmo-backup-2026-10-18.json`. В файл попадают все напоминания: включённые, выключенные
и завершённые, со всеми параметрами расписания, временными окнами и состоянием.
По завершении показывается сообщение с числом сохранённых напоминаний.

**Восстановить** — выбор JSON через системный файловый менеджер. Файл проверяется до любых
изменений: повреждённый или неподходящий показывает ошибку, текущие напоминания и будильники
остаются нетронутыми. Затем запрашивается подтверждение замены с указанием числа напоминаний
в файле и в текущем списке. После восстановления старые будильники отменяются, а уведомления
планируются заново из восстановленного набора. Прошедшие однократные напоминания сохраняются
в списке, но не планируются, поэтому потока пропущенных уведомлений не возникает.

Формат файла — тот же JSON, что и во внутреннем хранилище, поэтому копию можно прочитать
и отредактировать вручную. Префикс `ritmo-backup-` не обязателен: подойдёт любой файл
с корректным списком напоминаний.

## Известные ограничения

- В режиме Doze и при агрессивной экономии батареи система может задержать срабатывание.
  Приложение не обходит системные ограничения.
- Однократное напоминание, момент которого пришёлся на выключенное устройство, не
  восстанавливается: оно остаётся в списке с пометкой о прошедшем времени.
- Окна интервалов через полночь не поддерживаются.
- Автоматического резервного копирования и облачной синхронизации нет — копии создаются вручную.
- Названия тегов входят в резервную копию вместе с напоминаниями; определения пустых тегов
  в файл копии не попадают. Старая копия с полем `group` читается: группа становится тегом.
