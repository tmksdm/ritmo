# AGENTS.md — правила работы над Ritmo

## Роли

- **Агент-разработчик** (ZCode): пишет код, собирает APK, публикует релизы, ведёт документацию.
- **ChatGPT**: независимый архитектор и ревьюер, проверяет коммиты и заявленные результаты.
- **Пользователь**: окончательные решения, проверка на реальном телефоне, утверждение этапов.

## Главный приоритет

Быстро получать работающий результат, который можно установить на телефон и проверить.
Порядок приоритетов: работающий результат → надёжность основной функциональности →
минимальный размер и скорость → удобный интерфейс → улучшения по итогам практики.

## Что запрещено

- отдельные фазы планирования, новые роадмапы, дробление этапов на согласования;
- исследования гипотетических рисков, «десятки тестов ради покрытия», масштабные рефакторинги;
- функции сверх согласованного ТЗ (см. `PRODUCT.md`);
- тяжёлые зависимости, облака, серверы, аналитика, реклама, Firebase, WebView как основа UI;
- force-push, работа через Pull Request и отдельные ветки (работа идёт в `main`);
- публикация ключа подписи и паролей: ключ лежит вне репозитория, `keystore.properties` в `.gitignore`.

## Стек (не менять)

Kotlin, нативный Android SDK, Android Views/XML, `AlarmManager` + `BroadcastReceiver`,
локальное хранение, Gradle. minSdk 26, targetSdk — актуальный стабильный.
Release: R8 + shrinkResources, целевой размер APK ≤ 5 МБ.

## Процесс этапа

1. Реализовать согласованный объём этапа.
2. Проверить: сборку debug/release, версию и подпись APK, изменённые сценарии.
3. `./gradlew newVersion` — следующая версия по схеме `ггмм.дд.номер`
   (первая версия дня без номера, дальше `.2`, `.3`).
4. Коммит в `main`, push, GitHub Release с APK-ассетами.
5. Отчёт: этап, что реализовано, SHA и ссылка, путь/ссылка и размер APK, что проверено,
   реальные ограничения, статус.
6. Остановиться до ревью и проверки на телефоне. Следующий этап не начинать без разрешения.

## Подпись релизов

Постоянный ключ `D:\Pr\keys\ritmo-release.jks`, параметры подключения — `keystore.properties`
(в git не попадает). Без этого файла release собирается с debug-подписью и не годится для публикации.

## Сопровождение документации (постоянное правило)

Агент поддерживает актуальность `PRODUCT.md`, `PROJECT_STATE.md`, `HANDOFF.md` и `README.md`
самостоятельно, без напоминаний:

- при завершении существенного изменения проверять, какие сведения устарели, и обновлять
  только соответствующие документы;
- перед передачей результата на ревью убедиться, что `PROJECT_STATE.md` и `HANDOFF.md`
  отражают фактическое состояние: текущий HEAD, выполненную работу, открытые проблемы
  и следующий разрешённый шаг;
- историю не накапливать: устаревшее заменять, подробная история остаётся в Git;
- документация отражает факты: этап не объявляется завершённым до реализации
  и пользовательского утверждения;
- отдельные этапы, коммиты и согласования ради документации не создавать — обновлять
  её вместе с основной работой.
